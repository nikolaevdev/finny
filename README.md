# Питомец Финни

**Финни** — прототип Android-приложения для детей 7–11 лет, который объясняет планирование бюджета, осознанные покупки и накопления через заботу о виртуальном питомце. Ребёнок распоряжается только игровыми монетами: реальных платежей, банковских операций, регистрации и серверной учётной записи в приложении нет.

**Версия проекта:** `0.14.7+44` · **Платформа:** Android · **Пакет:** `ru.mishanikolaev.finny` · **Язык интерфейса:** русский.

> Текущий статус: функциональный прототип. Статическая проверка ресурсов и 324 спрайтов Финни прошла. После последнего исправления стартового widget-теста полный `flutter test`, `flutter analyze` и проверка APK на устройстве должны быть повторены на компьютере с Flutter SDK. Релизная подпись не настроена.

## Что делает приложение

Финни превращает финансовое решение в понятное игровое последствие. В начале периода ребёнок получает доход, распределяет его между категориями **«Нужно / Хочу / Коплю»**, выбирает покупки, решает задания и направляет остаток к цели. После периода приложение сопоставляет план с фактом и объясняет результат без оценки ребёнка как «хорошего» или «плохого».

| Возможность | Реализация в прототипе |
|---|---|
| Первый запуск | Короткое знакомство, локальный профиль и создание Финни |
| Игровые периоды | Пять последовательных периодов без ожидания календарных дней |
| Бюджет | План и факт по трём категориям, контроль доступных монет |
| Магазин | Восемь товаров: обязательные и необязательные покупки |
| Накопления | Три цели, пополнение и подтверждаемое снятие средств |
| Задания | Шесть задач по планированию бюджета, сбережениям и покупкам |
| Обратная связь | Четыре состояния настроения и три стадии развития питомца |
| Прогресс | История периодов, выполненные задания, цель и словарик |
| Для взрослого | Обзор прогресса и управление локальными данными после арифметического барьера |
| Демонстрация | Профиль с возможностью подтверждаемого сброса игрового сценария |

Приложение работает с локальными данными. Оно не заменяет финансовую консультацию и не использует настоящие деньги.

## Быстрый запуск

### Требования

- Flutter SDK с Dart, удовлетворяющим ограничению `^3.13.4` в `pubspec.yaml`. Проект разрабатывался под Flutter 3.47.5 / Dart 3.13.4.
- Android SDK и устройство либо эмулятор Android. В Gradle задан `minSdk = 26`.
- JDK 17 для Android-сборки.

Пути к Android SDK и локальные настройки машины не включены в репозиторий. На Windows сначала проверьте окружение:

```powershell
flutter doctor -v
flutter devices
```

Из корня проекта:

```powershell
flutter pub get
flutter run
```

Для полного локального прогона и отладочного APK:

```powershell
flutter analyze
flutter test
flutter build apk --debug
```

Файл сборки появится в `build/app/outputs/flutter-apk/app-debug.apk`. Каталог `build/` игнорируется Git; APK для демонстрации передаётся отдельно, если этого требует площадка сдачи.

На Windows в `android/gradle.properties` установлен `kotlin.incremental=false` для конфигурации с проектом на диске `F:` и Pub Cache на `C:`. При другой конфигурации это свойство можно пересмотреть после стабильной сборки.

## Сценарий демонстрации

1. Запустите приложение без локального профиля. После короткого экрана подготовки фона откроется знакомство с Финни.
2. Создайте профиль и выберите окрас, форму ушей и узор. Проверьте, что выбранная внешность сохраняется после перезапуска.
3. Откройте первый период и распределите доход по направлениям «Нужно», «Хочу» и «Коплю». Подтвердите план.
4. Купите обязательный товар и один необязательный. Посмотрите изменение баланса, заботы, настроения и историю покупок. Постоянные предметы появятся в комнате.
5. Решите финансовое задание сначала неверно, затем верно. Неверный ответ объясняется без штрафа; первое успешное прохождение выдаёт 10 монет. Повторное успешное прохождение того же задания награду не дублирует.
6. Выберите цель и пополните накопления. Откройте итог периода: приложение покажет план и факт по трём категориям.
7. Завершите несколько периодов, чтобы увидеть рост Финни. Пять периодов образуют полный демонстрационный цикл.
8. Откройте «Мой прогресс», словарик и раздел «Для взрослого». Сброс данных выполняйте только после демонстрации, поскольку он изменяет сохранённое состояние.

Все шесть заданий доступны из раздела «Задания». Демо-профиль можно вернуть к исходному игровому состоянию через защищённый взрослый раздел, сохранив имя и внешность Финни.

## Игровые правила

### Доход, расходы и задания

В начале игрового периода начисляются **120 игровых монет** с объяснением источника дохода. План фиксирует суммы для обязательных расходов, необязательных желаний и накоплений. Приложение не позволяет распределить или потратить больше доступного остатка. Итог завершённого периода сохраняется и не пересчитывается задним числом.

| Категория | Товары и цены, монеты |
|---|---|
| Нужно | Набор еды — 30; свежая вода — 15; уход за шерстью — 20; уютное место для сна — 25 |
| Хочу | Мяч — 25; дневник исследователя — 20; растение — 30; звёздная лампа — 45 |

Шесть заданий охватывают три темы: **планирование бюджета**, **сбережения**, **платежи и покупки**. Первое успешное решение каждого задания даёт 10 монет, всего не более 60 дополнительных монет за набор. Неудачная попытка не лишает уже достигнутого прогресса.

### Накопления и цели

| Цель | Стоимость, игровые монеты |
|---|---:|
| Уголок исследователя | 180 |
| Домик Финни | 260 |
| Поездка на фестиваль | 320 |

Смена выбранной цели не обнуляет накопления. После достижения стоимости пользователь подтверждает выполнение: стоимость списывается из накоплений, результат отмечается в прогрессе, а оставшаяся сумма сохраняется. Снятие накоплений также требует подтверждения.

### Настроение и развитие

Настроение — обратимый показатель от 0 до 100. Текущее состояние влияет на портрет, подпись, шкалу и выражение большого Финни.

| Значение | Состояние | Спрайт выражения |
|---:|---|---|
| 0–34 | Немного грустит | `quiet` |
| 35–59 | Спокоен | `calm` |
| 60–79 | Доволен | `happy` |
| 80–100 | Очень рад | `delighted` |

Стадии развития — **Малыш**, **Подрос**, **Уверенный Финни**. Рост зависит от истории нескольких завершённых периодов: удовлетворения обязательных потребностей, соответствия решений плану и регулярных накоплений. Текущее настроение само по себе не заменяет прогресс развития.

## Финни и визуальные ресурсы

Внешность задаётся тремя окрасами (бирюзовый, песочный, лавандовый), тремя формами ушей и тремя узорами. Для каждой из трёх стадий и четырёх эмоций подготовлен цельный спрайт:

`3 стадии × 3 окраса × 3 формы ушей × 3 узора × 4 эмоции = 324 WebP-файла`.

Один спрайт содержит тело и готовую мордочку. Во время отрисовки Flutter не совмещает отдельный слой рта с глазами и носом; это устраняет смещение маски при изменении окраса, ушей, узора и стадии. Двенадцать небольших портретов настроения используются в карточках интерфейса. Для больших изображений применяется ограничение ширины декодирования через `cacheWidth`.

| Путь | Назначение |
|---|---|
| `assets/images/finni/mood_sprite/` | 324 итоговых изображения персонажа |
| `assets/images/finni/mood_portrait/` | 12 портретов для карточек |
| `assets/images/finni/{stage,ears,pattern,appearance,mood}/` | Исходные материалы для пересборки, не перечислены в asset bundle |
| `tools/finni_face_sources/` | Подготовленные области мимики, измеренные смещения и манифест |
| `assets/images/{home,shop,goals,navigation}/` | Сцены и элементы интерфейса |

Готовые спрайты уже включены в проект. Для их повторной генерации нужны Python, Pillow, NumPy и OpenCV (`pip install pillow numpy opencv-python`):

```powershell
python tools/build_finni_runtime_assets.py
python tools/validate_finni_faces.py
python tools/render_finni_face_matrix.py
```

Последняя команда создаёт обзорные листы в `artifacts/`. Для проверки существующих файлов достаточно `validate_finni_faces.py`; генерация не нужна при обычной сборке Flutter. Подробности приведены в [документе о графике](docs/visual_assets.md).

## Архитектура и хранение данных

Проект разделён по игровым функциям. Интерфейс реализован на Flutter, маршруты — через `go_router`, состояние экранов — через `flutter_riverpod`. Профиль, игровое состояние и настройки хранятся локально с помощью `shared_preferences`.

```text
lib/
├── app/                 # приложение, маршруты, тема
├── core/                # общие виджеты и звук
└── features/
    ├── onboarding/      # знакомство
    ├── profile/         # локальный профиль
    ├── pet/             # внешний вид питомца
    ├── game/            # доменная логика, состояние и сохранение
    ├── home/            # главная комната
    ├── budget/          # планирование
    ├── shop/            # покупки
    ├── savings/         # цели и накопления
    ├── tasks/           # финансовые задания
    ├── period/          # итоги периода
    ├── progress/        # история и словарик
    ├── settings/        # параметры и инструкция
    └── adult/           # защищённый раздел
```

Доменная модель `GameState` содержит баланс, накопления, периоды, покупки и учебный прогресс. `PeriodSummary` хранит зафиксированный план и факт; `PetDevelopmentProgress` рассчитывает стадию по истории. Каталоги товаров и заданий отделены от экранов.

Формат сохранения — `GameState.schemaVersion = 6`; существующая миграция обрабатывает схемы 1–5. Поле `rewardedTaskIds` предотвращает повторное начисление монет. Настройки приложения сохраняются отдельно. При удалении локального профиля через взрослый раздел соответствующие игровые данные удаляются после подтверждения. Облачной синхронизации и восстановления после удаления в этой версии нет.

## Звук и настройки

На Android четыре коротких сигнала воспроизводятся через `SoundPool`, три фоновые музыкальные сцены — через `MediaPlayer`. Музыка переключается по разделам и повторяется циклически. Звуки действий и музыку можно отключать независимо; управление анимациями и повторная инструкция доступны в настройках. Системное уменьшение движения учитывается анимацией Финни и интерактивных элементов.

Музыкальные сцены: главная/знакомство; спокойные разделы (бюджет, задания, накопления); магазин/награды/итог периода. Ресурсы лежат в `android/app/src/main/res/raw/`. Подробнее — [docs/audio_assets.md](docs/audio_assets.md).

## Проверка и сборка

Основные команды из корня проекта:

```powershell
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
python tools/validate_release.py
python tools/validate_finni_faces.py
```

`validate_release.py` проверяет комплект ресурсов, подключение музыки и ключевые связи кода без Android SDK. `validate_finni_faces.py` декодирует все 324 спрайта и проверяет их соответствие вариантам внешности. Widget-тесты проверяют игровой цикл, экономику, сохранение, основные экраны, путь к спрайтам и переход анимации свечения кнопки. Стартовый widget-тест отключает только прогрев больших фоновых изображений, чтобы проверять маршрут онбординга независимо от асинхронного декодирования; обычное приложение прогревает их перед показом первого экрана.

**Проверено при подготовке этого архива:** статические проверки ресурсов и 324 спрайтов, чтение ZIP без ошибок. **Не подтверждено в этой среде:** `flutter analyze`, полный `flutter test`, сборка Android и устройство — Flutter SDK здесь отсутствует. Последний присланный пользователем прогон `flutter test` содержал одно падение стартового widget-теста; исправление включено в текущую версию, после чего требуется повторный прогон на его компьютере. Сообщения Pub о доступных новых версиях зависимостей не являются ошибкой тестов.

Для ручной проверки на Android пройдите сценарий выше, переключите все четыре эмоции и три стадии Финни, проверьте небольшую ширину экрана, постоянные покупки в комнате, звук, фоновую музыку, сохранение после перезапуска и возврат с экрана итога. Без этого APK следует считать демонстрационной сборкой.

## Ограничения и выпуск

- Это локальный прототип: серверной части, сетевой синхронизации, аккаунтов и реальных платежей нет.
- Содержимое `android/local.properties`, ключи подписи и локальные пути SDK не должны попадать в Git. Они исключены `.gitignore`.
- В `android/app/build.gradle.kts` конфигурация `release` пока использует **отладочную подпись**. Перед публикацией в магазине приложений необходимо настроить собственный ключ, безопасное хранение секретов и полноценную релизную сборку. APK с текущей release-конфигурацией нельзя считать готовым для публикации.
- Набор из 324 изображений увеличивает объём ресурсов. Время запуска, использование памяти и размер готового APK следует измерить на целевом Android-устройстве.
- Версию `1.0.0` имеет смысл присваивать после успешных тестов, проверки на устройстве и подготовки релизной подписи.
