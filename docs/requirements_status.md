| Элемент | Требование ТЗ | Текущая версия |

| Последовательные игровые периоды | не менее 5 | 5 без ожидания реального времени |

## Экономика заданий

Каждое из 6 заданий выдаёт 10 монет только за первое успешное прохождение. Максимальная дополнительная награда за весь набор заданий – 60 монет. Такой размер награды даёт понятный доход за обучение, но не отменяет ограниченность ресурсов одного периода: базовый периодический доход остаётся главным источником бюджета.

Если сохранение Этапа 11 уже содержит пройденное задание, оно остаётся пройденным. Для совместимости список полученных наград начинается пустым, поэтому такую награду можно один раз получить при повторном успешном прохождении задания. После этого повторные прохождения монеты не начисляют.

## Главный экран

Главная сцена показывает одну реплику Финни, два показателя состояния, ресурсы, активную цель и шесть переходов. Название следующего задания убрано из отдельной строки ради пространства для персонажа. Очерёдность заданий и награды не менялись: список доступен по кнопке `Задания`.

## Раздел для взрослого и управление данными

Разрушительные действия больше не находятся в обычных настройках. После арифметического барьера взрослый может:

- сбросить игровой прогресс с сохранением имени и внешности Финни;
- для демо-профиля сбросить демонстрационный сценарий к стартовому состоянию;
- удалить локальный профиль и игровой прогресс после отдельного подтверждения.

В детских настройках остаются только параметры комфорта и повторная инструкция `Как играть`.

## Совместимость сохранений

Этап 12 повышает формат состояния до `GameState.schemaVersion = 6` и добавляет `rewardedTaskIds` – список заданий, за которые уже была выдана награда. Сохранения схем 1–5 продолжают загружаться без сброса. У сохранений Этапа 11 пройденные задания сохраняются, а ещё не зафиксированную в старой версии награду можно получить один раз при повторном успешном прохождении.

## Следующие действия

По функционалу дополнительная разработка не запланирована. Три фоновых композиции уже включены в Android-ресурсы и привязаны к маршрутам приложения: основная тема, спокойный фон и музыка магазина/наград.

Перед публикацией требуется технический прогон на компьютере с Flutter SDK:

```bash
flutter clean
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

После сборки необходимо пройти основной сценарий на Android-устройстве или эмуляторе, проверить внешний вид Финни на трёх стадиях, покупки в комнате, четыре состояния настроения, звуковые сигналы и добавленные музыкальные треки. Затем можно настраивать release-signing и готовить сборку для RuStore.

## Что осталось перед публикацией

1. Получить чистые результаты `flutter analyze` и `flutter test`.
2. Собрать Android-приложение и проверить сценарий на реальном устройстве или эмуляторе, включая экраны 320×568 и 390×844.
3. Проверить все варианты ушей и узоров на трёх стадиях, четыре выражения лица, постоянные предметы комнаты, переключение трёх музыкальных сцен и циклы треков.
4. Настроить release-signing и подготовить релизные материалы для RuStore.

Эти пункты относятся к валидации и выпуску, а не к добавлению нового игрового функционала. До их выполнения версию `1.0.0` использовать не следует.
